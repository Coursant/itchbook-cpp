# 逐步实现与验收

| 阶段 | 交付 | 完成条件 | 状态 |
|---|---|---|---|
| M0 | 独立 C++17 工程、规范/架构/基准文档 | GCC/Clang 严格告警可编译，CTest 可跑 | 已完成 |
| M1 | 长度前缀读入，A/D，按 symbol BBO | 多 symbol、新增/删除、截断/非法状态测试；错误非零退出 | 已完成 |
| M2 | R/F/E/C/X/U 与其他类型的明确分类 | 官方格式长度与生命周期覆盖；真实样例可按定义重放 | 待做 |
| M3 | 参考实现、逐事件差分、公开夹具 | 所有支持的消息逐条比较订单/价位/BBO；失败最小化 | 待做 |
| M4 | 受界限保护的优化索引 | 溢出/越界/容量回退测试；结果与参考版一致 | 待做 |
| M5 | 可复现 benchmark、分析与简历材料 | 同机同输入对照，吞吐/延迟/内存，原始数据与命令公开 | 待做 |

推荐学习节奏：先在 CppTrader 找到 A/D 与 order reference 的处理路径，自己画状态转移；随后独立实现 M2 的 X/E/C/U，并用协议表验证字节偏移。M3 之后再看它的优化版 benchmark，分析数据结构开销。Liquibook 可用来学习订单生命周期和工程组织，但不是 ITCH 重放正确性的 oracle。

每完成一阶段，应在此表更新状态，在测试中补充反例，在基准报告留下构建命令和代码 SHA。不要将 Agent 写的阶段标成用户已掌握；用户需独立讲解和复现，才可作为面试能力证据。
