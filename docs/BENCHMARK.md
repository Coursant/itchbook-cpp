# 基准与对照方案（尚未执行）

先比较正确性，再比较速度。主基线是项目内朴素 `std::unordered_map<order_ref, Order>` + `std::map<price, aggregate>` 的**同语义**参考版；当前 M1 代码是此基线的起点。外部基线选 [CppTrader](https://github.com/chronoxor/CppTrader) 的 ITCH handler 与 market manager，固定提交 `39421f50ae673be34235e24eac95827220763652`。它的示例或优化版必须先确认涵盖相同消息、输入、输出和错误策略；若语义不等，只作为架构/性能参考，不声称直接胜出。

数据集：先用公开小样本做协议覆盖与逐事件差分；再记录完整交易日样本的来源、日期、解压后 SHA256、消息类型分布和 symbol 数。合成负载按 symbol 数、价位密度、A/E/C/X/D/U 比例、热 symbol 偏斜生成，并公开生成种子。分别测 **仅解析**、**仅应用预解码事件**、**端到端文件重放**，不能混报。

每组同机、同 CPU 亲和性、相同编译器/标志、相同文件缓存状态，预热后至少五次独立重复；报告 median、范围、消息/秒、每消息纳秒、峰值 RSS、错误数，并公开原始每轮结果。分析性能时可加 `perf stat`（cycles、instructions、cache-misses、branch-misses）。真实输入和合成输入分开呈现，避免缓存内短循环掩盖 I/O 与解析成本。任何提前过滤、跳过未知消息、错误处理差异都必须说明，不能放进同一速度排行。

简历亮点的证据门槛：逐消息差分无误；相同工作量下候选实现的收益可重复；异常路径与安全检查没有为了数字被删除。当前没有任何本机性能数据，因此不写倍数或纳秒指标。
